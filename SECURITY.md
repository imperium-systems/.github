# Security Policy

## Reporting a vulnerability

**Do not open a public issue for a security problem.**

Systems such as `Lictor` (anticheat), `Tabularius` (player data) or `Veredarius` (networking) protect live games. A publicly disclosed flaw can be exploited before a fix ships.

Report vulnerabilities privately, by either:

- email to **victor.jost@epitech.eu**, with `[SECURITY]` in the subject, or
- [GitHub private vulnerability reporting](https://docs.github.com/en/code-security/security-advisories/guidance-on-reporting-and-writing-information-about-vulnerabilities/privately-reporting-a-security-vulnerability), from the **Security** tab of the affected repository.

Please include:

- the affected system and repository (for example `Lictor` in `roblox`)
- the engine and version used
- steps to reproduce, or a proof of concept
- the impact you observed or expect

## What to expect

- Acknowledgement within **72 hours**.
- An initial assessment within **7 days**.
- Credit in the release notes once the fix is published, if you wish.

Please give us reasonable time to release a fix before disclosing the issue publicly.
